# PI-SPECTRUM: Reference-Free Privileged Self-Teacher Spectral Gains

**Research branch, authored 3 November 2026. NO native 7B GPU calibration, SFT,
or benchmark evaluation was performed during delivery.**

The method is a code implementation and falsifiable experiment hypothesis,
not a claim that the model already improves itself without correct labels.

## Exact scientific contract

The Self-Teacher and Student are the SAME current Qwen2.5-Coder-7B
checkpoint (no 27B, no API teacher). Training uses no fixed calibration
examples, reference answers, program execution, tests, verifier or external
environment feedback. The train-task view is reduced to ID/prompt/source/
split/chat-template keys before it reaches the Self-Teacher or LoRA SFT.

The Student sees its original coding prompt x. The frozen Self-Teacher
sees x PLUS an unverified short strategy plan c generated by the SAME model.
On the exact Student-generated continuation IDs y, compare:

    q_r,t(v) = stopgrad p_theta_r(v | x, c, y_<t)
    p_r,t(v) = p_theta_r(v | x, y_<t)
    L_PI = average_t KL(q_r,t || p_r,t)

The teacher and student prefixes have different token lengths; target
logits are aligned to the SAME continuation token IDs, never aligned
to equal raw sequence positions.

Compute gradients of L_PI with respect to native pre-RoPE/pre-normalization
K/V Linear outputs of the Student (including causal earlier prompt states).
For each selected K/V module m:

    C_r,m = sum_{i,t} g_i,t,m^T g_i,t,m / N_m
    C_r,m = U_r,m diag(lambda_r,m) U_r,m^T
    T_r,m(a) = U_r,m diag(a_r,m) U_r,m^T,  0.1 <= a_j <= 1

Freeze model and eigenspaces. Use finite projected-gradient optimization of
the teacher-to-intervened-student PI KL over 12 *unlabeled train prompts*.
A separate 6-train-prompt guard must not show worse PI KL than native.
Another disjoint set of 6 train prompts is used for native-to-steered
full-vocabulary forward KL <= 0.02 nats/token. Validate actual BF16
weight-folding on fit/guard/probe; otherwise use exact Identity.
No training reference labels are read.

Temporarily fold K/V operators ONLY while sampling training completions.
The PI method deliberately uses the repo's fixed SSD sampling override
(temperature=1.5, top_p=0.8, top_k=20) to make SSD a matched comparator.
Restore original model parameters before ordinary LoRA SFT on every raw
sample. Repeat on the next native student, recomputing plans, teacher
distributions, covariance and gain coefficients each round.

This is NOT a full OPST algorithm: no EMA teacher, no complete OPST
pseudo-verifier, no separate learned privileged-context generator, and
no Gated DeltaNet memory or learned novelty gate. Those are separate
research extensions, not silently implied by this source release.

The PI config deliberately has ONLY train, validation and eval split paths;
it does NOT have data.calibration. The baseline plain/ssd config uses the
legacy four-split pipeline metadata but neither arm trains on calibration
answers. Run paths and source fingerprints are separate from main results.

Output per PI round includes pi_plans.jsonl, pi_rollouts.jsonl,
pi_covariances.pt, pi_operators.pt, pi_audit.json,
pi_provenance.json, calibration_provenance.json, and the
ordinary generated train/SFT/evaluation/complete receipts.
The operator and model identity hashes are checked before resume; never
rebuild a missing pre-SFT PI operator using post-SFT weights.

## Preparing the GPU host

Keep any active main-branch experiment checkout untouched:

    git fetch origin research/pi-selfteacher-spectral-20261103
    git worktree add ../SPECTRUM-pi origin/research/pi-selfteacher-spectral-20261103
    cd ../SPECTRUM-pi
    python -m pip install -e '.[train,test,analysis]'

Re-use existing pinned MBPP train/validation/eval split files. If missing,
prepare original project splits with the canonical procedure:

    python -m improving.cli prepare --dataset mbpp --output-dir data/mbpp --revision 4bb6404fdc6cacfda99d4ac4205087b89d32030c

Point model.name in a NEW local copy of the YAML at the real Qwen2.5-Coder-7B
checkpoint. Do not modify model/config/output identity during a run. First:

    bash scripts/run_pi_spectrum.sh check

Then do a separate ONE-round smoke/qualification run with rounds=1 and a
distinct output_dir. Measure actual H100 memory and model behaviour, check
tokenizer-prefix agreement and BF16 folding/guard/probe receipts. Only after
qualification run the ten-round protocol:

    bash scripts/run_pi_spectrum.sh run configs/pi_spectrum/pi_selfteacher_7b_r10_4096.yaml

    bash scripts/run_pi_spectrum.sh resume configs/pi_spectrum/pi_selfteacher_7b_r10_4096.yaml

For unchanged Plain/SSD comparator methods with the exact same 7B/4096/6144
budget and original seed:

    bash scripts/run_pi_spectrum.sh run configs/pi_spectrum/matched_plain_ssd_7b_r10_4096.yaml

Execution is foreground and explicit. Generated Python is UNTRUSTED;
the supplied config uses a Docker evaluator. Qualify Docker isolation,
image identity and time/memory limits before executing candidate programs.
If no program execution is desired even for final scoring, in a new
configuration set evaluation.backend to none, but no Pass@k/AST scores
are then obtained. Evaluation test outcomes NEVER feed the PI optimizer.

## Resource and interpretation guardrails

The 10-round PI arm plans 291*16*10 = 46,560 SFT generation samples
and 500*64*11 = 352,000 evaluation samples including base, plus
24 short plans and 24 short student rollouts PER ROUND and repeated
full-vocabulary PI forward/backward passes. These are planned counts,
not GPU-hours. A prior 7B successful run is not proof that the extra
PI gradient steps fit. Prefer H100 80GB qualification, >=64GB RAM,
>=500GB disk, and measure actual usage. All ten checkpoints are
retained by default for trajectory diagnostics.

The 64-token short rollout/probe KL does not bound long 4096-token
generation. An unverified plan may be wrong; reduced PI KL is NOT
verified correctness. The a_j<=1 constraint may force identity.
The 6-example guard is a training-side fit-veto, NOT a correctness
oracle, and does not guarantee generalized performance.

Predeclared primary metrics: native Pass@1/16/64, correct AST richness
C64, matched-correct D4, paired task confidence intervals,
identity fallback, probe KL, realized token exposure, and three-state
pre-native / pre-spectral / post-native transfer diagnostics. Additional
required baselines before paper claims: plan-shuffled / plan-removed,
random spectral basis, isotropic gain and direct PI on-policy distillation,
all with same training/compute budgets and multiple independent seeds.
THESE EXTRA ABLATIONS ARE NOT IMPLEMENTED in this commit.

## Research lineage and priority

SSD: https://arxiv.org/abs/2604.01193
OPSD: https://proceedings.mlr.press/v306/zhao26be.html
OPST: https://arxiv.org/abs/2610.32770
LOPD: https://arxiv.org/abs/2608.13040

Privileged self-teaching and on-policy distillation are existing ideas.
The candidate contribution here is PI-KL-derived full-spectrum K/V gain
learning inside repeated generation -> ordinary SFT. Distinctness and
benefit over these baselines are HYPOTHESES, not established results.
