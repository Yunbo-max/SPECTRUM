## 1. 研究结构与范围

保留阶段C（条件下的失效模式与结构性限制）和D（数学机制构造与局部实验验证）。阶段B提供论文、代码、实际问题和串行只读社区讨论线索。允许C/D按具体缺口返回B的对应节点，不要求每次重跑B。D发现问题契约有误可返回C。D通过VERIFIED_FOR_SCALEUP后自动进入E；E继续承担完整设置、冻结、大规模比较和确认，不由D的局部证据代替。

此次只调整B与C/D的回访接口、C/D职责和执行准入、D→E证据交接；不将所有84节点改为无约束自由跳转，不修改其他插件。旧节点ID可用于历史定位，但新展示必须准确表示数学与实验共同参与，不能保留旧“先Gate0成功才允许获取证据”的依赖。

## 2. C：发现并验证具体限制

C从一个可定位的既有方法/架构及合法使用场景开始。形成代码执行图和数学依赖图：输入、状态、算子、顺序、信息可用时机、约束和真实成本。

支持两类问题；不能全部硬编码为failure_census：

1. 假设失配：某个有来源的真实条件改变，使原方法关于数据、信息、噪声、稳定性或资源的假设不成立，产生可测量损失。
2. 过强依赖：某种固定计算、等待、更新或求解规则并非在全部研究条件下必要，带来可避免的成本、干扰或质量限制。旧方法可以准确且正确实现；不要求它先在任务上失败。

这些是可并存的问题描述，不是通过改贡献标签获得PASS。每个问题仍需要明确端点、实际条件、相关强替代和可追踪证据。新环境可包含计算/信息约束和数据条件，须有真实应用或明确科学问题依据，不能仅为让指定baseline失败而选择。

### C的循环单元

- 来源与实现：固定具体既有方法、代码版本及有效baseline设置。
- 数学诊断：写出所依赖的假设/计算规则，推导条件变化或放宽依赖后的可观察预测。
- 观测：在现有模型和benchmark上采集适当中间量、任务表现与成本。
- 判别性干预：用最简单的可执行干预比较竞争解释；区别相关性与机制证据，记录副作用和不能识别的原因。
- 评估：检查实现/调参不足、额外信息、算力和随机性是否足以解释观察。
- 更新：形成problem_contract或返回具体来源/诊断步骤，不强迫一个失败条件一定成立。

C的简单干预可以包含跳过、固定/随机选择、替代、预算匹配等，为识别问题服务；它不是已被认可的新架构。代码执行和必要对照必须允许在C发生，否则无法验证问题。数据来自已发表benchmark/已有数据集及透明合法分组；不能改变参考答案或挑选成功样本来制造证据。适配协议必须说明与官方设置的差异。

problem_contract包含：既有方法、条件/约束及来源、候选失效或依赖、原假设、观测量、任务/成本后果、竞争解释、干预与实际结果、分母/不确定性、对照范围、未解决项及版本谱系。

PROBLEM_SUPPORTED只表示限定条件下存在值得研究的限制；不能写成普遍结构不可能性。未找到问题时记录未支持的结论并返回B/C寻找实质新解释，不制造问题。

## 3. D：推导机制、实现并验证方法

D消费C的问题契约，但数学与代码持续互动：

1. 抽象目标、允许信息、约束和待优化量，辨别模型假设与算法求解误差。
2. 提出并比较可解释该限制的机制与更简单替代。
3. 推导可计算的更新规则/状态流/信息流、近似误差和适用边界。
4. 实现足以完整执行诊断比较的方法；每个关键算子关联到代码位置。
5. 使用合格baseline、简单替代和必要消融在现有模型/数据上运行真实比较。
6. 回读预测、原始输出与不确定性；收益、代价、反例和无效尝试全部保留。
7. 结果指向数学、代码、测量或问题定义的具体修正；必要时返回B的具体步骤或C。

新方法不必增加模块，可以删除、替代、重排、近似、共享或选择计算。公式本身不能认证原创性；检索/代码功能比较必须检查最接近已有工作。数学推导可指导代码，代码行为也可推翻所用数学近似，不强制所有实用预测都包装成定理。

单模型、单数据集允许作为D的局部范围，但不豁免真实端到端执行、公平baseline、关键反事实、数据泄露/分母检查和适合结论的不确定性分析。方法效果与机制解释是不同义务：只涨分不能自动验证解释。

## 4. 数学与代码共用的可审查记录

每个命题/诊断使用同一组引用，不创建相互脱节的长篇数学文档和调参日志：

| 字段 | 内容 |
|---|---|
| question/claim | 本次要区分的解释和科学主张 |
| assumptions | 条件、允许信息、近似及有效范围 |
| mathematical_object | 状态/算子/依赖/目标；推导或猜想状态 |
| code_binding | 对应函数、张量、配置及精确代码身份 |
| observable | 如何从真实运行中测量相关量 |
| intervention/control | 实际改动及简单/强反事实 |
| prediction/falsifier | 在看本次结果前声明的预测和否定条件 |
| evidence | 协议、实际run、原始结果、误差及分析引用 |
| revision | 解释更新、失效证据范围及保留义务 |

自动检查验证身份、数据流、完整性和任务状态；数学正确性、干预可识别性、基线合理性和科学解释由独立reviewer审核。禁止仅因JSON有效或代码exit=0就将研究标为verified。

## 5. 条件与统计要求

优先检查边界内/附近/外的可行条件或离散条件组合；不存在可操作阈值时不强造阈值。充分条件失效不意味着结论必然反转，边界外预测必须来自实际推导。相关性和小状态变化不能单独证明更新无用。

质量不下降需要明确非劣界限与足够精度，不能由p值不显著推出。任务内采样和任务bootstrap不代替训练间变化。搜索超参数、方法和条件的曝光记录保留，C/D结果标为开发证据。D中的预定复核可降低明显过拟合风险，但不能将反复使用的数据包装成E的未见确认集。规模与重复数量按具体方差、效应和资源确定，不设通用“3种子即通过”。

对于质量—成本主张，应检查端到端成本、实际精度/延迟/内存及新增决策开销。对于表征/记忆/状态更新主张，应检查相关信息是否更有效地保存、访问或更新；系统加速本身不能证明表达能力增强。无需强迫所有贡献都属于模型能力改进。

## 6. B↔C↔D局部回访

原B节点包括L01检索、L02主题/引用图、L03精读、X02图表附录、L04代码复现、X03日志网页、L05新证据监测。可根据诊断问题选择一个具体节点回访，然后携带新增来源返回原研究位置。

小红书帖子与评论作为线索，串行只读，遵循已授权访问；trick必须回到原论文、源码或实际实验核验。没有新线索时不重复相同检索。新工作未满足某已接受证据的适用条件，只使受影响记录失效，不重跑整个阶段。

回访请求记录origin、target、证据缺口/竞争解释、期望产物、return位置和影响版本。worker提出，reviewer审核，controller应用合法B/C/D转移。涉及并行/外部作业时先对账；不能有任意jump字段、隐藏全局重启或重复启动GPU任务。不擅自添加用户未授权的累计时间/轮数上限。

## 7. D的VERIFIED_FOR_SCALEUP与自动进入E

这是进入正式扩大实验的证据关口，区分三类状态：工程运行有效、C的问题得到支持、D的方法值得扩大验证。

VERIFIED_FOR_SCALEUP至少要求：

- 当前C问题契约仍有效，条件具有可解释意义；不是弱baseline或错误评分制造的问题。
- D的数学假设/机制与实际实现可对应；已知推导缺口如实标注。
- 已有完整真实局部实验，采用公开已有benchmark、模型、数据和可核查evaluation。
- 主效果和关键机制预测获得限定范围内足够支持，包含合格baseline与最必要的简单反事实；实用意义和误差被处理。
- 主要执行错误、欠调参、额外信息/预算和随机波动解释已经检查；未消除的解释不能隐藏。
- 近邻工作审查足以支持继续投入；已有方法的重新命名不能认证创新。
- 固定候选/代码/协议版本，保留已试全部方法与结果，并列出E仍须解决的泛化、规模、重复与确认义务。
- 独立reviewer读回证据并通过；程序验证记录完整性及合法状态。

用户明确选择验收后自动进入E，不新增人工逐次批准。没有通过时返回对应B/C/D工作；执行错误先debug，不作科学否定。合法负结果可以归档，但不会将失败方法伪装成通过并启动其大规模优越性实验。

E仍执行S02/S03/S04等既有正式职责，复用未变的环境和实现，扩大比较范围/规模，冻结确认协议并真实运行。E的新反证可通过显式回访事件重新打开受影响D/C证据，保留已消耗资源和结果，不静默重置。

## 9. 原文线索的取舍
